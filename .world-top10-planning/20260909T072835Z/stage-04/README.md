# STAGE-4-QUALITY — 품질·통합·내구성

1. 쉬운 말 한 문장 목표: 핵심 기능이 다양한 기기·망·권한·실패에서도 믿을 수 있게 한다.
2. 사용자에게 보이는 단계 완료 모습: 빠르고 읽기 쉽고, 실패하면 이유와 복구 행동이 보인다.
3. 포함 범위: 성능·접근성·보안·오프라인·PWA·광고 표식·관측·운영 내구성.
4. 명시적 제외 범위와 이유: 광고 실제 승인·법률 자문은 사람 결정 전 확정하지 않는다.
5. 진입 조건 체크리스트: STAGE-3 핵심 여정 인수·콘텐츠 상태 모델 통과.
6. 이전 단계에서 받는 입력: 실제/합성 구분, 오류 코드, 상태 배지, 운영 로그.
7. 산출물 파일 목록: 성능 보고, 접근성 매트릭스, 보안·광고·관측 계약, 회귀 묶음.
8. 요구사항·격차·결정 ID 목록: REQ-009·011·017·018·020, GAP-009·011·017·018·020.
9. 작업 의존 관계와 실행 순서: observability→performance→accessibility→security→ads→ops drill.
10. 병렬 실행 가능 작업: 정적 보안, Lighthouse/브라우저, UI 접근성, 관측 대시보드 fixture.
11. 절대 순차 실행 작업: CMP 정책 전 광고 요청, 운영 로그 전 공개 인수, 접근성 실패 해결 전 release candidate.
12. 예상 변경 파일·기호·설정: `apps/shared/live*`, `tests/*`, `tools/*` 후보.
13. 데이터·API·UI 계약 변화: metric event, error envelope, consent state, audit event.
14. 정상 흐름: 측정→회귀→오류 주입→복구→품질 임계치 판정.
15. 빈·로딩·부분 성공 흐름: 저속·오프라인·광고 차단·자료 없음에 안전한 대체 UI.
16. 실패·권한 거부·오프라인·복구 흐름: 장애 공지·재시도·롤백·캐시 무효화·권한 최소화.
17. 접근성·다국어·모바일·PC 조건: TalkBack/Narrator 사람시험, 키보드, 대비, 360/390/1280/1920.
18. 보안·개인정보·권한 조건: CSP/URL/XSS, 동의, 데이터 분리, 감사로그.
19. 성능·용량·비용 예산: LCP/CLS/TBT p75와 API 5xx를 반복 관측하되 기준은 사전 승인.
20. 자동 시험 묶음: 단위·API·브라우저·PWA·보안·성능·회귀.
21. 수동·실기기·외부 서비스 시험 묶음: 사람 접근성·CMP·운영 장애 훈련은 외부 대기.
22. 중단 신호와 되돌리는 순서: 개인정보 노출·광고 오인·성능 임계 초과면 release candidate 폐기→원인 격리.
23. 종료 조건과 필요한 증거: 품질 임계치·실패 복구·보안·접근성·운영 관측 증거.
24. 다음 단계 인계 체크리스트: release candidate, rollback rehearsal, 법률·운영 인수 패킷.
