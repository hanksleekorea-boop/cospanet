# STAGE-3-CORE — 핵심 여정·필수 기능

1. 쉬운 말 한 문장 목표: 사용자가 굿딜을 찾고 판단하고 공유·저장·가계부로 이어지게 한다.
2. 사용자에게 보이는 단계 완료 모습: 발견→상세→행동→결과와 빈·오류·복구가 끊기지 않는다.
3. 포함 범위: 온라인·매장 딜, 지역·지점, 출처·신선도, 공유·포인트, 가계부 연결, 알림.
4. 명시적 제외 범위와 이유: 실권리·실제 운영 데이터는 운영자 확인 전 공개하지 않는다.
5. 진입 조건 체크리스트: STAGE-2 API·계정·UI 계약 통과.
6. 이전 단계에서 받는 입력: owner key, source schema, 공통 상태, 96필드 카드.
7. 산출물 파일 목록: 핵심 화면·API·콘텐츠 운영 큐·알림·가계부 시험.
8. 요구사항·격차·결정 ID 목록: REQ-004, REQ-007·008·014·015·016, GAP-004·007·008·014·015·016.
9. 작업 의존 관계와 실행 순서: source rights→deal model→store key→freshness→share→budget→notification.
10. 병렬 실행 가능 작업: UI 카드·필터, 신선도 계산, 가계부 계산, 알림 contract.
11. 절대 순차 실행 작업: 권리 승인 전 공개, 가계부 동의 전 서버 전송, 중복 방지 전 포인트 적립.
12. 예상 변경 파일·기호·설정: `packages/gooddeal/*`, `packages/budget/*`, `apps/shared/*` 후보.
13. 데이터·API·UI 계약 변화: deal/source/store/observation/ledger/point/notification.
14. 정상 흐름: 검색→조건 확인→저장·공유→검토→가계부 행동.
15. 빈·로딩·부분 성공 흐름: 지역 자료 없음·출처 지연·페이지 부분 응답에 다음 행동 제공.
16. 실패·권한 거부·오프라인·복구 흐름: 만료·철회·중복·저속·오프라인 큐·재연결 멱등.
17. 접근성·다국어·모바일·PC 조건: 일본어 문구, 360/390 터치, 1280/1920 키보드.
18. 보안·개인정보·권한 조건: 가계부 원문과 공개 딜 분리, 포인트 현금화 차단.
19. 성능·용량·비용 예산: 목록 페이지 cursor, 카드 payload 상한, 알림 중복키.
20. 자동 시험 묶음: API·계산·상태·중복·신선도·포인트·가계부 회귀.
21. 수동·실기기·외부 서비스 시험 묶음: 실제 출처·점포·파일럿·Android는 외부 대기.
22. 중단 신호와 되돌리는 순서: 권리 없는 공개·예상액의 지출화·포인트 현금화 시 중단→항목 격리.
23. 종료 조건과 필요한 증거: 핵심 여정 정상/빈/오류/복구 인수와 실제 콘텐츠 권리 슬롯.
24. 다음 단계 인계 체크리스트: 품질 지표·접근성·보안·운영 로그와 지역·콘텐츠 샘플.
