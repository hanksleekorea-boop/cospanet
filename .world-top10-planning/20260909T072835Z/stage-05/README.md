# STAGE-5-RELEASE — 공개 인수·복구·안정화

1. 쉬운 말 한 문장 목표: 실제 서비스로 공개해도 된다는 증거를 한 장부에서 확인한다.
2. 사용자에게 보이는 단계 완료 모습: 지정 주소에서 로그인·저장·공유·삭제·복구와 지원이 실제로 작동한다.
3. 포함 범위: 공개 URL·OAuth·D1·실제 콘텐츠·운영·법률·Android·접근성·백업·롤백·인수인계.
4. 명시적 제외 범위와 이유: 운영자·법률·계정이 미확인인 항목은 완료로 표시하지 않는다.
5. 진입 조건 체크리스트: STAGE-4 품질·보안·성능·접근성 release candidate 통과.
6. 이전 단계에서 받는 입력: 모든 시험 결과, 오류·복구 로그, 운영·정책 문서.
7. 산출물 파일 목록: 출시 통과표, 복구 checksum, 운영 runbook, 공개 링크 검증.
8. 요구사항·격차·결정 ID 목록: REQ-001~020, GAP-001~020, DEC-0001~0020.
9. 작업 의존 관계와 실행 순서: external gates→A/B E2E→content/operator→device/human→rollback→release.
10. 병렬 실행 가능 작업: 문서 인수, 링크 점검, 정적 보안, 장애 runbook rehearsal.
11. 절대 순차 실행 작업: OAuth/D1/DNS 확인 전 A/B E2E, 운영자 확정 전 삭제·문의 인수, 모든 필수 조건 전 공개.
12. 예상 변경 파일·기호·설정: 공개 설정·secret reference·release manifest는 별도 승인 후에만 후보.
13. 데이터·API·UI 계약 변화: 운영 SLA·공개 정책·지원·삭제·복구 계약 확정.
14. 정상 흐름: 공개 주소→OAuth→저장→공유→운영→삭제/복구.
15. 빈·로딩·부분 성공 흐름: 미지원 지역·느린 응답·부분 콘텐츠·로그인 전 상태 설명.
16. 실패·권한 거부·오프라인·복구 흐름: 401/403/503·장애 공지·rollback·백업 restore.
17. 접근성·다국어·모바일·PC 조건: 승인 Android 한 대, 사람 TalkBack/Narrator, 키보드, 일본어, 360/390/1280/1920.
18. 보안·개인정보·권한 조건: 비밀값 비노출, 최소 권한, 삭제·보존·감사, 광고 동의.
19. 성능·용량·비용 예산: 공개 p75·API 오류·D1 비용·로그 보존 상한을 운영자가 승인.
20. 자동 시험 묶음: 전체 회귀, release manifest, 링크·JSON·배포 표면, 보안·성능.
21. 수동·실기기·외부 서비스 시험 묶음: OAuth·D1·DNS·운영자·실콘텐츠·Android·법률·광고.
22. 중단 신호와 되돌리는 순서: 필수 게이트 미평가·보안/법률 실패면 공개 금지→이전 candidate→장애 공지.
23. 종료 조건과 필요한 증거: 필수 게이트 미확인 0, 실제 링크·계정·기기·운영·복구 증거 모두 연결.
24. 다음 단계 인계 체크리스트: 출시 후 7/30일 관측, 사건·비용·복구 runbook, 다음 개선 백로그.
