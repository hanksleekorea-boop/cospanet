# DealCatch 서비스 유사도·우수 관행 분석

생성: 2026-08-20 UTC · 범위: 현재 프로젝트의 읽기 전용 증거와 공개 서비스 자료 · 판정: **부분 완료**

## 1. 대상 서비스 한 문단 설명

DealCatch는 한국어권 절약형 쇼핑 사용자가 게시판 기반 딜을 탐색하고, 검색·가격·판매처·기간 필터와 30일 가격 흐름으로 판단하며, 저장 검색·공유·관심어 알림·투표·댓글·신고로 정보를 보완하는 무료 웹/PWA입니다. 서버 계정이나 결제 흐름은 현재 핵심 가치가 아니며, 사용자 자료는 기기 저장소 중심으로 보존·내보내기·복원하도록 설계되었습니다. 이는 파일·자동 검사·공개 화면 근거에 따른 설명이며, 실제 이용자 규모나 시장 성과를 뜻하지 않습니다.

## 5. 합성된 이상 기준

`ideal-standard.json`의 16개 기준을 사용했습니다. 모두 시작·개인화, 핵심 가치, 품질·성장, 신뢰·상용화, 운영·확장의 다섯 묶음을 포함합니다. 경쟁 화면을 복제하지 않고, 다음 행동 단위로 정규화했습니다: 관심 설정, 검색/필터, 가격 판단, 딜 검증, 알림 관리, 기기 자료 제어, 오프라인, 접근성, 성능, 공개 품질, 개인정보·법적 안내, 상용화 투명성, 지원, 이용자 생성물 운영, 시장 학습, 출시 운영.

## 7. 예비 수준 점수와 증거 완성도

Readiness Hub 엔진 결과는 별도 파일에 기록합니다. 이 분석의 해석상 기술 기능은 강하지만, 법적·운영·수익화 증거는 의도적으로 비어 있습니다. 따라서 전체 상용화 수준을 자동 시험 최고치와 동일시할 수 없습니다.

## 8. 강점 3개

1. 서버 계정 없이도 검색 상태와 개인 자료를 저장·공유·내보내기·복원하는 안전망이 구체적입니다.
2. 모바일 PWA의 실제 동작 근거가 강합니다: 오프라인, 서비스 워커 업데이트, 390px 터치/대비, 실제 유휴 Android 한 대의 공개 화면 확인이 있습니다.
3. 커뮤니티 딜 탐색의 기본 흐름은 검색·가격 흐름·투표·댓글·신고까지 이어져 직접 비교군의 최소 행동을 넓게 덮습니다.

## 9. 필수 기준선 갭

1. 운영 주체·공개 지원 경로 부재.
2. 법률 검토가 끝난 이용약관·개인정보 고지와 사용자 권리 경로 미확인.
3. 사람에 의한 TalkBack·Narrator 탐색 시험 미실시.
4. 이용자 생성물 신고의 운영 규칙·처리 목표·이의 절차 미확인.
5. 실제 오류 관찰·사고 대응 담당자와 연락 절차 미확인.

## 10. 경쟁력 기준 갭

1. 가격 이력의 출처·확인 시각·범위 설명.
2. 알림의 미리보기·조건별 해제·기기 내 한계 설명.
3. 검색 제안·오타 보정·동의어·최근 검색.
4. 선택형 관심 설정과 개인화된 첫 화면.
5. 상용화 전 공개 가능한 신뢰 설명(광고·제휴·추천 근거).

## 11. 차별화 기회

- **로컬 우선 신뢰:** 계정 없이도 검색 조건과 복원을 제공하되, 어떤 자료가 기기에만 있는지 한 화면에서 설명합니다.
- **딜 판단 설명:** 가격 곡선에 출처·확인 시각·표본 수·품절/신고 신호를 조합해 “왜 이 딜을 봐야 하는지”를 설명합니다.
- **알림 절제:** 경쟁 서비스의 다채널 알림보다 먼저, 맞은 조건·빈도·해제 방법을 사용자가 예측할 수 있게 합니다.

## 13. 사용자 없이 실행 가능한 개선 과제 20개

다음은 **운영자 신원·법률 문구·결제·실기기 사람 시험처럼 결정을 요구하는 항목을 제외한 경우**입니다.

1. 가격 이력 화면에 확인 시각 자리와 데이터 한계 설명을 설계한다.
2. 검색어 제안의 로컬 자료 구조와 단위 시험을 만든다.
3. 무결과 화면의 대체 검색어를 추가한다.
4. 저장 검색의 조건 미리보기 화면을 만든다.
5. 알림의 일시 중지·재개·삭제 흐름을 정리한다.
6. 알림 매칭 사유를 화면에 표시한다.
7. 오프라인 배너와 마지막 동기화 시각을 추가한다.
8. 로컬 자료 목록을 보여 주는 화면을 만든다.
9. 자료 전체 삭제의 확인·실행·검사 흐름을 만든다.
10. 첫 방문 관심 설정의 건너뛰기 흐름을 만든다.
11. 댓글/신고 상태의 사용자 피드백을 보강한다.
12. 신고 분류를 구조화하고 제출 전 안내를 추가한다.
13. 키보드 이동과 포커스 순서 전체 재검사를 추가한다.
14. 동적 글자 크기/좁은 폭 화면 검사를 늘린다.
15. 공개 URL·깨진 링크·콘솔 오류 읽기 검사를 자동화한다.
16. 성능 예산과 추세 비교를 자동 검사에 넣는다.
17. 서비스 워커 자료의 신선도/갱신 문구를 검증한다.
18. 내부 공개 검사 결과 색인을 생성한다.
19. 최소 운영 문서 템플릿을 준비한다(실제 연락처는 결정 뒤 입력).
20. 목표가 감시의 사용자 과업 시제품을 만들고 자동 검사한다.

## 14. 운영자 결정 필요 항목

- 서비스 운영 주체의 법적 이름, 사업자 고지 범위, 공개 문의 채널과 응답 책임자.
- 실제 이용약관·개인정보 처리방침의 법률 검토 및 적용 국가 범위.
- 광고·제휴·유료 기능·결제·해지·환불을 도입할지와 정책.
- Android를 PWA/보조 실행기로 유지할지, 서명된 스토어 앱으로 갈지.
- 실제 사용자 자료나 분석 정보를 수집할지, 한다면 목적·보존 기간·동의 방식.
- 이용자 생성물 모더레이션의 사람·시간·이의 처리 책임.

## 15. Android 실기기 시험 상태

**실기기 검증됨(범위 한정):** 2026-08-19에 명시적으로 고른 유휴 Android API 35 한 대에서 로컬 한국어 상태 6개와 음성 완료, 공개 v0.21의 제목·HTTPS·32개 카드를 확인했습니다. 다른 연결 기기는 사용하지 않았습니다. **미실시:** TalkBack으로 사람이 실제 탐색하는 시험, 서명된 Android 배포 채널 시험, iPhone 시험. 자동 브라우저/PWA 검사는 실기기 사람 시험과 혼동하지 않았습니다.

## 16. Readiness Hub 엔진 결과와 한계

엔진 결과는 `readiness-analysis.json`과 `readiness-analysis.md`에 있습니다. 이 엔진은 공개 렌즈의 항목과 입력한 증거만 계산합니다. 비교군 점수는 공식 자료에서 확인한 행동을 0–5로 정규화한 분석값이며, 시장 점유율·앱 평점·가격·성능 실측을 뜻하지 않습니다. 법적·운영·결제 항목의 미확인은 임의의 0점으로 바꾸지 않았습니다.

## 17. 결론

**부분 완료.** DealCatch는 공개 무료 서비스로서 핵심 딜 탐색, 로컬 자료 보존, PWA 품질, 자동 브라우저 검사 근거가 강합니다. 그러나 운영 주체·지원·법적 고지·이용자 생성물 운영·사람 접근성 시험은 소스 코드만으로 완료할 수 없으며, 실제 상용 운영 또는 결제를 열기 전 별도로 충족되어야 합니다. 이번 분석은 법률 자문, 준수 인증, 또는 시장 성과 보증이 아닙니다.
